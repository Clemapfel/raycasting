<Faq question="Does this game use AI? What does &quot;procedural&quot; mean?" id="ai-policy">
    Excuse the juristic tone, but we consider this important to make clear: no text, images, music, sound effects, code, story / gameplay ideas, concept art, documentation, or other content in the game, on this page, or any social media associated with "Chroma Void", was generated by an <Link text="LLM" href="https://en.wikipedia.org/wiki/Large_language_model" />, <Link text="T2I" href="https://en.wikipedia.org/wiki/Text-to-image_model" />, I2I, or other prompt-based content generation model, third-party or otherwise.

    "Procedural", here, refers to generating assets algorithmically. The suite of algorithms used does not include <Link text="stable diffusion" href="https://en.wikipedia.org/wiki/Stable_Diffusion" /> (which is a type of T2I), or any kind of architecture that involves deep-learning on third-party, scraped, bought, or stolen data of any kind. No external machinery such as cloud- or physical server infrastructure was used to generate any assets in the game.

    For an example of a "non-AI" procedural assets, let's assume the game needs a sound effect of a string being plucked. You can either
    + have AI generate it from a prompt (this method was __not__ used at any point in development for obvious reasons)
    + record a physical string being plugged using a microphone in real life, or buy a recording of a physical string being plugged. Assets of this type are in the game, but are not considered procedural.
    + model the string as a mathematical function in code, virtually excite that model, then measure the functions output and export it as a sound file. The game then plays back that generated sound file during gameplay, with neither AI nor a microphone involved in any step of the process.

    This same method of procedural generation was also applied to create textures and backgrounds. Animations for many objects including the player are generated in real-time using the physics simulation.

    **Level design is not procedural**, every object is placed by hand. There is no "random generation" for placement of any gameplay-relevant objects - as would be common in other genres such as rogue-lites.
</Faq>

<Faq question="What are the minimum specifications my computer needs to play?" id="system-specs">
    For the best experience, Chroma Void requires

    + Windows or Linux operating system, Mac should be possible but is not officially supported
    + >4gb of RAM
    + a processor with >8 cores
    + a graphics card with >1gb of VRAM
    + a graphics card driver that is OpenGL 4.3, OpenGL ES 3.1, and/or Vulkan 1.0 compatible

    To check if your current machine matches or exceeds these requirements, follow these steps depending on your operating system:

    ### Windows

    1) press windows + r, enter `dxdiag`, then press enter
    2) under the `System` tab, check if `RAM` is larger than `4096mb`
    3) under the `System` tab, check if `Processor` mentions more than `8 CPUs`
    4) under the `Display` tab, in the `Device` area, check if `Approx. Total Memory` is larger than `1024mb`
    4) under the `System` tab, check if `DirectX Version` is `DirectX 11`, `DirectX 12`, or larger

    ### Linux

    Open the "Terminal" app, then enter the following commands, pressing enter after copypasting them:
    1) `nproc`. Verify the resulting output is larger a number larger than 8
    2) `grep /proc/meminfo)`. Verify the resulting output is larger than `2000000 kb`
    2) `glxinfo | grep GL_ARB_compute_shader`. The resulting output should be **non-empty**

    If all of these pass, your computer should be capable of running Chroma Void with all graphics settings enabled. For
    machines below these specifications, graphics options exist that vastly reduce the graphics card requirements, but
    result in a poorer overall visual experience.
</Faq>

<Faq question="My game crashed. How do I report a bug?" id="bug-report">
    If you encounter a bug or an error that terminates the game (resulting in a red screen with an error message), proceeds as follows depending on your operating system.

    Data you send using the below method does not contain identifying information and will not be stored or used for any purpose other than review during bugfixing.

    ## Windows

    1) open the "File Explorer" app
    2) copypaste `%APPDATA%/chroma_void/logs` into the top bar in the file explorer to navigate to the logs folder
    3) locate the newest file in this directory by sorting by "Date modified"
    4) right click the file, choose "Compress to... > ZIP File"
    5) send the resulting `.zip` file along with a description of the events preceding the error to `bugs@chroma-void.com`

    ## Linux

    1) open the "Terminal" app
    2) copy paste `cd "${XDG_DATA_HOME:-$HOME/.local/share}/ game/logs"` into the terminal and press enter to navigate to the logs folder
    3) copy paste `file="$(ls -t | head -n 1)"; gzip -k "$file" && echo "created ${file}.gz"` into the terminal and press enter
    4) send the resulting `.gz` file along with a description of the events preceding the error to `bugs@chroma-void.com`

    ## Mac

    MacOS is currently not officially supported. If you'd like to contribute to the development of a mac version of the game, feel free to send bug reports to `bugs@chroma-void.com`.
</Faq>

<Faq question="What engine does the game run on? What tools were used during development?" id="tools-used">
    "Chroma Void" runs on a custom, bespoke engine that is currently not available to the public. It is written in <Link text="LuaJIT" href="https://luajit.me/" /> and <Link text="GLSL" href="https://www.khronos.org/opengl/wiki/Core_Language_(GLSL)" />, with additional <Link text="TypeScript" href="https://www.typescriptlang.org/" />, <Link text="C++" href="https://en.cppreference.com/" />, <Link text="Python" href="https://www.python.org/" />, and <Link text="sclang" href="https://doc.sccode.org/Help.html" /> performing auxiliary functions.

    Programming Libraries used:

    + <Link text="Box2D" href="https://box2d.org/" /> for environmental collision and spatial queries
    + <Link text="Love2D" href="https://love2d.org/" /> for rendering, sound playback, file i/o
    + <Link text="Slick" href="https://github.com/erinmaus/slick/" /> for polygon triangulation

    All other features such as player physics, real-time lighting, particle simulation, and the flow-system, were implemented from scratch.

    Tooling used during development:

    + <Link text="SuperCollider" href="https://supercollider.github.io/" /> for sound effect generation
    + <Link text="Tiled2D" href="https://www.mapeditor.org/" /> for level design
    + <Link text="Marmoset Hexel" href="https://marmoset.co/hexels/" /> for pixel art
    + <Link text="Inkscape" href="https://github.com/inkscape/inkscape" /> for creating certain assets such as icons
    + <Link text="Astro" href="https://astro.build/" /> for creating this website
</Faq>

<Faq question="Is the game safe to play for people with photosensitivity?" id="accessibility">
    Despite the admittedly overwhelming amount of colors and speed of play, great care was taken to not make the game straining to look at, even for prolonged periods. The accessibility options furthermore include a dimming slider and a toggle to turn off certain animations.
</Faq>
